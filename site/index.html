UNDER THE NUMBERS

A useful estimate starts with visible assumptions.

01

Describe the work

Choose a task or describe an active day. Presets translate that into model calls, starting context, context growth, and output. Every assumption is editable.

02

Count repeated context

Each model call can reread instructions, files, conversation history, and tool results. We sum those calls, separate cached reads and writes, and include reasoning in output.

03

Apply the actual offering

Multiply each token category by its published rate, then scale by tasks, active workdays, and people. Cloud, region, deployment, and context band matter.

See the formula, assumptions, and limits

Cost = (fresh input × input rate + cache reads × read rate + cache writes × write rate + output × output rate) ÷ 1,000,000

For call i, input is min(starting context + i × context growth, context cap). Cache reads are the reused prefix times the hit percentage; the first call starts cold. Cache writes are a percentage of the remaining uncached input. Missing cache rates use the full input price, with a visible warning. Retries add proportional token overhead.

The context cap approximates truncation or compaction. Actual summary-generation calls, parallel agents, model routing, cache expiration, and tool payloads can change consumption; include them in the assumptions or use measured totals. Context growth includes retained answers and tool results, so output is not added to context twice.

Lighter and heavier scenarios vary calls per task (default 0.5× and 2×), allowing context to grow with longer tasks. Measured mode varies total token volume instead. These are sensitivity scenarios, not confidence intervals, a maximum bill, or measured averages. The same workload across models does not imply equal quality, speed, or task success.

Repository size is not a billable quantity. A large repo can be inexpensive when the agent retrieves a few files; a small repo can be expensive when an agent repeatedly revisits context. Starting context means what is actually sent, including instructions and tools.

Only text/code token charges are included. Excludes subscriptions, tool/search fees, sandboxes, retrieval, embeddings, storage, networking, provisioned capacity, taxes, and negotiated discounts. A listed price does not establish model access or government authorization. Check your account’s deployment and invoice.

Grounding and calibration

Preset numbers are explicit design assumptions, not published benchmarks. The billing mechanics follow OpenAI’s pricing documentation, Anthropic’s caching documentation, and Azure’s caching documentation. Anthropic’s cost-management guidance also recommends using a pilot to establish your own baseline. Record token totals from a few real chat and agent sessions, then use Measured usage to replace the illustrative assumptions.
